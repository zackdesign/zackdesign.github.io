Zack Design has published **[mintosh](https://github.com/isaacrowntree/mintosh)**, a set of scripts that turns **Linux Mint Xfce** into a close copy of current macOS on an old Mac that Apple no longer updates. It has the macOS 26/27 "Liquid Glass" look, in light, dark or automatic. It also covers the whole move: back up the Mac from a second Mac, sort the files, install Mint, then three scripts for the system, the look and the keyboard.

It was built for one person: the owner of a 2013 MacBook Air (MacBookAir6,1, 4 GB of RAM), whose last macOS was Big Sur. The goal wasn't Linux that looks a bit like a Mac. It was a computer she can sit down at and use without learning anything new: the Apple menu where it was, ⌘C and ⌘Tab doing what they did, Spotlight on ⌘Space, and her files where she left them.

## Theming is the easy 20%

The look comes from people who have already done it beautifully. [MacTahoe](https://github.com/vinceliuice/MacTahoe-gtk-theme) is a careful recreation of the macOS Tahoe theme, icons and cursors. [picom](https://github.com/yshui/picom) does the blur behind glass, and [Toshy](https://github.com/RedBearAK/toshy) does the Mac keyboard. Plank is the dock, and Touchegg reads the trackpad gestures.

What mintosh adds is the wiring between them, and the parts a theme can't give you:

- **The menu bar.** On the left: the Apple menu, then the active app's name in bold and its own File, Edit and View menus, lifted out of the window (`xfce4-appmenu-plugin`). On the right, the status icons in macOS's order and the date the way macOS writes it ("Mon 26 Oct 9:41 AM"). The bar itself has no background: like Tahoe, the text sits on the wallpaper with a faint shade behind it.
- **The Apple menu.** It's a real menu, not a launcher: About This Computer, System Settings, Appearance, App Store, Force Quit, Sleep, Restart, Shut Down, Lock Screen and Log Out, with separators where macOS has them. It's Xfce's own applications menu pointed at a custom `.menu` file, whose entries live outside the normal app folders so they don't also turn up in search.
- **Spotlight, Launchpad and Mission Control**, more on these below.
- **The Mac keys and gestures.** ⌘C, ⌘V, ⌘Q, ⌘W and ⌘Tab; ⌘⇧3 saves a screenshot to the Desktop as "Screenshot 2026-10-26 at 09.41.12.png", with no Save dialog. F3 and F4 do what they say on the key. Three fingers up opens Mission Control, three fingers sideways changes desktop, and a thumb-and-three-finger pinch opens Launchpad.
- **The 2013 hardware.** An SSD the installer can't see without `intel_iommu=off`; a desktop that froze after about an hour until SATA link power saving was turned off (and kept off, because the battery-saver TLP turns it back on); the Broadcom Wi-Fi and FaceTime camera drivers; a fan controller; and battery warnings that use the same percentage the menu bar shows. The kernel's own battery figure reads lower on this Mac, so a warning at "20%" would otherwise arrive while the menu bar still says 26.

## 4 GB means nothing stays running

A 2013 MacBook Air has 4 GB of RAM, and Chrome would happily use all of it. So the rule was that anything macOS keeps resident only exists here while it's on screen.

**Spotlight and Launchpad are [rofi](https://github.com/davatorium/rofi)**, a launcher that starts when called and exits when closed. I tried Ulauncher first, the usual Spotlight stand-in on Linux. It stays in memory at 100 MB or more, which on this machine is a browser tab.

**Mission Control is a short-lived Python/GTK program** that reads the open windows through Wnck, Xfce's window-list library. It draws live previews of them from the compositor's copies, so windows that are covered still show. Across the top is the Spaces bar: click a desktop to go there, + to add one, ✕ to remove the last. Drag a preview onto a desktop to move the window. Click empty space, press Esc or swipe down to close.

![Mission Control: a "Desktop 1" button and a + button across the top, and below them previews of a Finder window and a Text Editor window, each labelled with the app's name.](/images/blog/mintosh-mission-control.jpg)

Two bugs from building it, because they show how these things fail:

- **Dragging a window to a desktop did nothing.** GTK only starts a drag if the widget was registered as a drag source before the handler that takes the click. The order was the other way round, so the click handler won every time and no drag ever began. Swapping two lines fixed it.
- **The labels said "Bulk Rename" under every Finder window.** The labels come from each app's `.desktop` file, the same name the menus use, so it says "Calculator" rather than `gnome-calculator`. But Thunar's bulk-rename tool is also started as `thunar`, and its entry matched first. The fix is to skip entries marked as hidden.

## Launchpad: a click outside has to close it

macOS's Launchpad closes when you click anywhere outside the icons. rofi has an option for that, `-click-to-exit`, but it only works when rofi's window is smaller than the screen; a full-screen rofi has no "outside".

So mintosh's Launchpad is two windows. The back one is full screen: a tiny GTK window showing the wallpaper, blurred and darkened. In front of it, rofi is a centred box whose background is the matching slice of that same blurred picture, so the two line up. Clicking outside the box closes it, as on a Mac.

![Launchpad in dark mode: a search field at the top and a grid of app icons with their names on a blurred, darkened wallpaper.](/images/blog/mintosh-launchpad.jpg)

It shows the same apps as Mint's own menu, so nothing goes missing in the move. Typing filters them; one click opens an app, and Return opens the best match.

Return with *no* match was a nasty surprise. rofi then runs whatever was typed as a shell command. Type "settings manager", press Return, and you get a full-screen "Failed to execute: 'settings manager'". Worse, typed text gets run at all. Both Spotlight and Launchpad now hand rofi a small wrapper, `open-app`. It only starts a command if that program is what some installed app's `.desktop` file launches. Anything else does nothing, which is also what macOS does.

## Light, dark and automatic

`appearance light|dark|auto`, or Apple menu → Appearance…, switches everything that has two looks:

- the theme, icons and window borders;
- the menu bar's text colour and the Apple logo;
- the dock, Spotlight, Launchpad, Mission Control and notifications;
- the wallpaper set;
- apps that follow the system colour scheme (Chrome, LibreOffice, GTK 4).

Auto is light from 7:00 to 19:00.

Each of these took longer than it should have, for the same reason: Xfce caches more than it says.

- **Xfce only reloads a theme when the theme's name changes.** On the first run, the setup set the name to MacTahoe-Light a few seconds before MacTahoe was installed. Xfce found nothing by that name and drew plain ✕ □ – buttons. Setting the same name again later changes nothing, so the setup now sets Xfce's default theme for a second first.
- **The panel reads its stylesheet and the Apple logo only when it starts.** So switching to dark left black menu-bar text on a dark wallpaper until the panel was restarted.
- **picom read one line of its config as an error and quit, and nothing said so.** The line was a window rule picom 11 couldn't work out the type of. There was no blur, no rounded corners and no shadows: just Xfce's flat compositor, which looks almost right, so it went unnoticed. The fix was two characters, `@:c`.

## What's tested, and what isn't

mintosh is tested in an [OrbStack](https://orbstack.dev) virtual machine running Mint 22.3 Xfce on a Mac, at the Air's 1366x768. `test/mintosh-test.py` uses xdotool to press keys and click, and Linux's accessibility tree to find buttons by name. It checks that:

- each shortcut reaches the mintosh helper it's bound to;
- Launchpad covers the screen, opens an app on one click, opens the best match on Return, and closes on Esc, on F4 again and on a click outside;
- Mission Control labels windows with their apps' names, adds and removes desktops, moves a window that's dragged onto a desktop, brings a clicked window to the front, and closes all three ways;
- each trackpad gesture runs what it should.

It deliberately doesn't test Toshy or Touchegg. Both are well-tested upstream projects. The first version of the test drove them through fake kernel input devices, and it mostly ended up testing the VM's device plumbing. (OrbStack's machines turned out to create only the first two of those devices' nodes, so the third and fourth silently didn't exist.) The test now presses the keys Toshy *sends* and runs the commands mintosh gives Touchegg, which is the part mintosh owns.

The other check is the Air itself, with the person who uses it.

## Known issue

The global menu plugin (`xfce4-appmenu-plugin` 0.7.6, the version Mint 22 ships) sometimes crashes when a Chrome window moves to another desktop. The panel restarts it on its own; if it crashes twice in a row, the panel asks whether to restart it, and the answer is yes.

## Try it

On any Linux Mint 22 Xfce machine, Mac or not, run scripts 3, 4 and 5 from the [README](https://github.com/isaacrowntree/mintosh#4-set-up-on-the-new-install). The hardware fixes only switch on when that hardware is present. Everything is English by default, with a second language as an option (`LANG2=es_CO`, `KBD=es`). If you're moving someone off an old Mac, steps 1 and 2 back it up and sort their files from a second Mac before anything is wiped.

Issues and pull requests are welcome, especially from anyone with a 2014 or 2015 MacBook to try it on.
